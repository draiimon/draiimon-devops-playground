PART 5 - SPEAKER SCRIPT: SOLUTION PRESENTATION
Junior DevOps Engineer Exam 2026
Mark Andrei Castillo

Format: 12 presentation slides. The screenshots are visual evidence; this script is a speaking guide for the presentation.

SLIDE 1: Opening

I will present the work as one delivery story: Linux foundation, Docker packaging, CI/CD automation, Kubernetes availability, then reflection.

------------------------------------------------------------------------

SLIDE 2: Overall approach

I worked from the foundation upward. Each part produced something the next part could use, which kept the troubleshooting scope clear.

------------------------------------------------------------------------

SLIDE 3: Architecture

The API and UI are separate services. Compose is the local environment, GitHub Actions is the delivery boundary, and Kubernetes is the runtime boundary.

------------------------------------------------------------------------

SLIDE 4: Linux

I completed the Linux command and scripting requirements and documented the results. The main lesson was to make system state observable and repeatable.

------------------------------------------------------------------------

SLIDE 5: Docker

I created separate production-oriented containers for the API and UI and used Compose to run them with MySQL. The screenshot shows the healthy local result.

------------------------------------------------------------------------

SLIDE 6: CI/CD pipeline

The pipeline is ordered as verify, build, test, publish, and notify. Publishing happens only after the quality checks pass.

------------------------------------------------------------------------

SLIDE 7: CI/CD evidence

The screenshots show the successful delivery result and notification evidence. I am keeping optional security scanning and live rollback as future work.

------------------------------------------------------------------------

SLIDE 8: HA design

I chose Kubernetes because replicas, Services, Ingress, probes, HPA, and PDB directly map to the high-availability requirements.

------------------------------------------------------------------------

SLIDE 9: HA evidence

The runtime evidence is stronger than a manifest alone: it shows replica state, traffic behavior, and 20 out of 20 successful requests during a controlled node failure.

------------------------------------------------------------------------

SLIDE 10: Challenges

The key challenges were source alignment, database alignment, clean CI runners, and distinguishing rollout health from real traffic health.

------------------------------------------------------------------------

SLIDE 11: Trade-offs

Minikube was practical for this time-limited exam. With more time I would add security gates, immutable digests, rollback testing, managed staging, and observability.

------------------------------------------------------------------------

SLIDE 12: Closing

My takeaway is that reliability is a chain of verified boundaries. Each tool has a clear job, and each important claim has evidence behind it.

------------------------------------------------------------------------
